# ADR-001：Fleet Hub 资产边界与首版出站语义

- 状态：已采纳
- 日期：2026-09-08
- 适用范围：Fleet Hub 首版、公司资产、采购与任务地图兼容

## 背景

现有系统的 Fleet Dock 展示任务快照中的 Actor。它们拥有任务 ID、路线、遥测和车机编组关系，但并不代表玩家购买并持有的公司库存。物流运营沙盘需要长期存在的公司资金、车队实例和采购记录，同时不能让尚未建立的任务配载与地图生成能力看起来已经完成。

## 决策

1. 公司账户和车队实例由 Spring Boot 与 MySQL 持久化，按签名访客身份隔离。前端只用服务端快照替换本地展示状态，不在浏览器自行结算余额或创建资产。
2. 公司资产与任务 Actor 在身份和业务数据上保持独立。Fleet Dock 同时展示任务编组和公司资产摘要，但不把公司资产写入 `MissionContext`，采购设备也不会创建新任务 Actor。运行时允许用当前出站资产替换既有 Actor 的三维模型与名称，并为明确标注的独立空中车型选择对应运动模式；Actor ID、冻结任务路线和任务数量不随之改变。
3. “出站/召回”只允许真实状态 `GARAGED ↔ DEPLOYED`。地面和空中分类各自最多允许一台资产处于 `DEPLOYED`；同类新设备出站时，后端在同一事务内自动召回原出站设备。没有任何同类出站资产时，地图不分配该类任务载具。此规则不建立物流中心坐标、不播放出站动画，也不表示资产已完成订单配载。
4. VTOL 重载运输飞行器标记为独立空中载具。它在任务第一轮推进时直接进入自己的空中路线，不等待地面车辆到达放飞点；完成后停在自身航线回收点，不绑定车辆。地图始终根据它自己的冻结空中路线及空中路线进度计算位置，不执行遗留 `mission.pairs` 的车载坐标和停机位姿态覆盖。普通轻型无人机继续保留旧任务的兼容车载姿态；三轮车不展示 F-350 警示灯、停机台，也不宣称已解锁 Drone Bay。
5. DEV MODE 是服务端能力控制的价格覆盖。允许时仅把采购价格改为 0；车型存在性、资产所有权、幂等命令和状态转换校验照常执行。基础/生产配置默认关闭，本地 Docker 默认开启。
6. 经营目录 `fleet-catalog/1.1.0` 将城市厢式运输车退役，不再展示或允许新增采购；为避免破坏既有访客数据，历史资产记录仍保留在数据库，但不计入当前车队快照。Cybertruck 位于 Peterbilt 之前并定价 ¥76,000，Peterbilt 定价 ¥98,000。
7. 当前原型允许出售处于 `GARAGED` 状态的设备，售价固定为车型目录正常价格。出售在事务内增加公司余额、写入 `SALE` 账本并以命令幂等；资产记录标记为已售而不物理删除。开发定价只覆盖采购成本，因此本地开发环境中免费采购的设备也按目录原价回收；生产环境默认关闭开发定价。该全价回收规则将在折旧与残值系统上线时被替换。

## 后果

- 可以在不改变任务 Actor 身份和冻结路线的前提下，用玩家当前唯一出站的地面/空中资产驱动地图模型；VTOL 会启用独立空中推进与遥测语义。
- 刷新页面后公司余额与资产状态继续存在，重复采购命令不会重复扣款或生成设备。
- 车库中的设备可以按目录原价出售；已出站设备必须先召回，重复出售命令不会重复入账。
- 现阶段的绑定属于车型映射及 VTOL 运动模式选择；不能从“已出站”推断独立任务占用、载货情况、物流中心位置或完整调度关系。VTOL 仍沿任务已有空中路线运行，不代表已经建立新的物流订单仿真。
- 订单收入、维修、折旧、车库容量、升级树和 Drone Bay 均不属于本 ADR 的实现范围。
