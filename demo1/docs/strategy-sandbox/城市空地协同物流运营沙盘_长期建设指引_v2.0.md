# 城市空地协同物流运营沙盘：长期建设指引

> 文档类型：产品、玩法与技术共同基线
> 版本：V2.0
> 更新日期：2026-09-10
> 适用对象：产品、设计、前端、后端、仿真算法、三维资产、测试与项目 Agent

## 1. 产品愿景

本项目在百度地图三维真实城市空间上构建一套可经营、可调度、可成长、可复盘、可优化的空地协同物流运营沙盘。

玩家从有限资金、少量设备和一个物流节点起步，选择订单与运力，规划车辆和航空器路线，应对道路、空域、续航和时效约束，完成交付并根据经营结果继续投资。

一句话目标：

> 让玩家在合肥真实城市地理底座上，用有限资金、车辆、航空器、时间和基础设施，建立高利润、高准时率且具备风险韧性的物流网络。

正式名称：**城市空地协同物流运营沙盘**
英文名称：**Urban Air-Ground Cooperative Logistics Sandbox**
品牌简称：**SkyFleet Logistics**

## 2. 产品原则

1. **真实城市是主要舞台。** 百度地图三维空间、道路关系和 BD-09 坐标是业务位置的统一基础。
2. **玩家经营一家公司。** 资金、资产、订单、成本、收益和成长必须形成闭环。
3. **利润重于流水。** 里程、能耗、时效、违规和设备投资都会影响最终结果。
4. **空地运力各有边界。** 地面车辆适合批量与干线运输，航空器适合小件、加急与道路受限区域。
5. **协同必须有条件。** 车载航空器能力需要设备、场景和调度条件支持，不能成为所有任务的固定最优解。
6. **后端保持权威。** 前端只呈现状态和提交意图，不独立判定任务或资金结果。
7. **每笔资金可解释。** 收入、成本、奖励、处罚、采购和出售进入同一账本。
8. **随机必须可复现。** 相同版本、Seed、参数和操作得到相同任务与结果。
9. **策略必须可复盘。** 计划、事件、遥测、决策、资金和失败原因形成完整证据链。
10. **智能能力受规则约束。** 语言模型不能绕过后端资格、数值、排序和安全门禁。

## 3. 目标用户

| 用户 | 核心价值 |
| --- | --- |
| 普通体验者 | 在真实城市地图上完成直观的空地配送挑战 |
| 竞赛评委与展示观众 | 快速理解百度地图、实时仿真与物流策略的结合 |
| 教学用户 | 学习车辆与航空器的成本、约束和调度差异 |
| 算法开发者 | 在可复现任务上比较路线、派单和协同策略 |
| 物流运营研究者 | 分析设备配置、准时率、利用率、能耗与利润 |

## 4. 核心经营循环

```text
查看任务与约束
      ↓
选择车辆和航空器
      ↓
生成并比较配送方案
      ↓
开始任务并处理实时事件
      ↓
完成交付与经营结算
      ↓
购买、出售、充电和调整车队
      └──────────────→ 下一轮经营
```

每一轮必须向玩家提供至少一个有后果的选择，例如更换运力、接受更高风险路线、提前绕飞、提高载重倍率或保留现金。

## 5. 任务系统

### 5.1 任务生成

任务实例由以下输入共同决定：

- 运营区域与模板版本；
- 生成器、随机算法和规则版本；
- Seed 与玩家参数；
- 已出站的具体地面和空中资产；
- 百度实时路线或模板保底路线；
- 空域、交通、航程、返航余量和会合约束。

生成结果必须保存为不可变制品。任务运行不得依赖后来重新调用路线服务或重新执行生成器。

### 5.2 任务生命周期

```text
生成预览 → READY → 开始运行 → RUNNING → COMPLETED / FAILED / STOPPED
```

任务开始前再次校验冻结资产。资产已召回、出售、被其他运行占用或状态版本变化时，必须拒绝开始并要求重新生成。

### 5.3 任务内容

- 地面配送点与空中配送点；
- 地面路线、空中路线、放飞点与回收点；
- 交通信号计划；
- 2—4 种互动空域主题；
- 配送收益、时效奖励和操作挑战奖励；
- 电量预算、返航余量与会合时间；
- 检查点和实际遥测时间线。

## 6. 车队与设备

### 6.1 资产模型

玩家拥有的是具体资产实例，而不是只有展示意义的车型数量。每个实例至少包含：

- 稳定资产 ID 与车型 ID；
- 所有者公司；
- `GARAGED` 或 `DEPLOYED` 状态；
- 当前电量、充电起点和状态版本；
- 活动任务占用关系；
- 采购与出售账本引用。

### 6.2 权威属性

| 属性 | 地面车辆 | 航空器 |
| --- | --- | --- |
| 速度 | 决定路线推进与时效 | 决定航线推进和会合时间 |
| 满电航程 | 决定里程耗电 | 决定飞行耗电与返航能力 |
| 运载倍率 | 放大地面配送收益 | 放大空中配送收益 |
| 机动响应 | 可作为车型差异 | 决定绕飞、爬升和返航动作响应 |

电量耗尽时设备在精确可达位置停止，任务进入失败状态。召回车库后按现实时间充电，充电未满也可按当前电量重新出站。

### 6.3 车队经营

- 新公司获得有限启动资金与基础地空运力。
- 采购必须校验目录版本、服务端价格、余额和幂等键。
- 出售只允许车库中且未被任务占用的资产。
- 出售保留资产与账本记录，不做物理删除。
- 开发定价开关只能改变采购价格，不能绕过所有权与状态门禁。

## 7. 经济系统

### 7.1 账本

每笔资金变化记录：

- 交易 ID 与稳定业务幂等键；
- 类型、金额、交易前后余额；
- 任务、资产、Actor 或空域引用；
- 仿真时间、规则版本与结构化明细；
- 创建时间与公司所有权。

余额不得脱离账本单独修改。

### 7.2 收益与成本

收益包括地面配送、空中配送、时效和高难度操作奖励。成本包括资产投资、后续维护、能耗和违规处罚。

单任务核心指标：

```text
任务净收益 = 已获得配送收益 + 奖励 - 处罚 - 任务运营成本
```

长期指标：

- 净利润与现金安全边际；
- 准时率与任务成功率；
- 车辆与航空器利用率；
- 单位里程和单位订单成本；
- 空驶、等待、能耗与违规率；
- 投资回收期和车队结构效率。

## 8. 空域与交通规则

### 8.1 空域类型

| 类型 | 主要决策 |
| --- | --- |
| 绝对禁飞区 | 提前侧向绕飞，侵入立即处罚 |
| 风险空域 | 接受更高等效耗电或选择绕飞 |
| 高度走廊 | 在合法高度带内穿越或侧向绕飞 |
| 临时禁飞区 | 根据激活时间选择绕飞或爬升 |

空域判定使用真实三维线段扫掠和高度范围，不以单帧点命中代替。建筑碰撞在进入权威规则前必须明确标记为 `NOT_EVALUATED`。

### 8.2 地面交通

- 路口信号由任务级 Seed 冻结；
- 地面车辆遵守停车线、红灯等待和允许右转规则；
- 等待计入仿真服务时间并影响时效收益；
- 播放倍速不能改变经济结果。

## 9. 交互与信息架构

### 9.1 经营规划态

- 公司余额与车队中心；
- 车型对比、三维预览、采购、出售、出站和召回；
- 区域选择、任务生成、路线与收益预览；
- 电量不足、约束冲突和保底路线提示。

### 9.2 运行调度态

- 三维任务空间与空地 Actor；
- 任务阶段、速度、电量、路线和连接状态；
- 空域冲突、可执行动作和后果提示；
- 实时收益、罚款、倍速、中止和跟随视角。

### 9.3 结算复盘态

- 收益、奖励、处罚与净结果；
- 地面和空中实际轨迹；
- 关键事件、检查点和决策时间线；
- 设备耗电与剩余运力；
- 下一步投资或调度建议。

## 10. 技术架构原则

1. 前端不得根据动画位置直接发放收益或完成任务。
2. 后端用单调 revision 发布状态，SSE 支持增量恢复。
3. MQTT Topic、数据库记录和内存状态按运行 ID 分区。
4. 任务实例、运行、资产与账本必须带所有权边界。
5. 坐标系、距离、速度、时间、金额和电量单位必须显式。
6. 外部 Provider 必须有超时、失败状态和确定性降级路径。
7. 模型与图片的来源、许可、哈希和加载策略必须可审计。

## 11. 智能调度边界

智能能力分为三层：

1. **规则计算层**：后端计算候选资格、距离、耗时、电量、成本、风险和排名。
2. **解释层**：语言模型将结构化事实转为可读说明。
3. **决策层**：操作员批准或拒绝建议，系统保存决策证据。

语言模型不得：

- 修改资格、排名和数值；
- 隐藏规则失败或 Provider 降级；
- 直接写入账本；
- 在命令链路不可用时声称已经执行；
- 获取浏览器端或服务端密钥。

## 12. 路线图

### P0：经营闭环稳定化

- 动态任务、资产冻结、地空配送、结算和回放稳定运行；
- 车队采购、出售、出站、召回与充电形成闭环；
- 规则版本、幂等账本和访客隔离完成自动化验证。

出口标准：新访客可以从启动资金开始完成一轮配送并看到可解释净结果。

### P1：成本与订单深化

- 引入订单重量、体积、时窗和服务等级；
- 增加能耗、维护、空驶和延误成本；
- 建立按订单、车辆和运营周期聚合的经营报表。

出口标准：不同车型和路线不存在永久固定最优答案。

### P2：车载航空器协同

- 车辆成为移动仓库、充电点与航空器起降平台；
- 约束放飞、回收、载荷转移与会合窗口；
- 比较独立配送和协同配送的综合成本。

出口标准：协同仅在满足距离、载荷、时间和回收条件时具备优势。

### P3：多车多机与市场变化

- 多订单并发、批量派单和多设备资源冲突；
- 可复现的订单市场、拥堵、天气、空域和故障；
- 车队利用率、现金流和服务等级成为长期经营目标。

出口标准：玩家需要持续调整车队结构与调度策略。

### P4：优化与研究模式

- 基准启发式、车辆路径与空地联合优化；
- 同一场景下的策略对比、批量运行和结果导出；
- 鲁棒性、成本、准时率和计算时间多目标评价。

出口标准：算法结果可复现、可解释、可与基线公平比较。

### P5：区域与专业能力扩展

- 在合肥内部增加更多物流节点和运营区域；
- 接入经过许可的真实参数与外部数据；
- 提升大规模车队、长周期经营和专业分析能力。

出口标准：扩展不会破坏已有存档、规则版本和可复现性。

## 13. 测试与完成定义

### 自动化测试

- 任务生成确定性、约束满足与无解场景拒绝；
- 车型速度、航程、电量与运载倍率；
- 空域扫掠、动作验证、罚款与挑战奖励；
- 交通信号等待和倍速独立性；
- 采购、出售、充电、任务占用与幂等账本；
- SSE revision、断线恢复、回放和检查点回退；
- 访客越权与并发状态冲突；
- Provider 未配置、超时与失败降级。

### 每次交付必须完成

1. 前端单元测试与生产构建通过。
2. 后端 Maven 测试通过。
3. 相关模型完整性校验通过。
4. Compose 相关镜像重新构建并重建容器。
5. 所有容器健康，`http://127.0.0.1:8088` 可达。
6. 文档、环境变量模板、接口和实现保持一致。
7. 没有密钥、临时测试制品或未授权资源进入 Git。

## 14. 安全与资产治理

- 生产环境必须更换数据库口令和 Cookie 签名密钥。
- 浏览器地图 AK 与服务端路线 AK 分离。
- 日志不得输出 Cookie、密钥、完整个人标识或敏感 Provider 响应。
- 公开部署必须配置 HTTPS 与 Referer 白名单。
- 第三方资产必须保存作者、来源、许可证、哈希和变更记录。
- 授权不明确的资产不得进入公开提交包。

## 15. 决策与版本治理

以下内容必须显式版本化：

- 任务模板、生成器与随机算法；
- 路线制品与坐标系统；
- 车队目录与设备属性；
- 经济、空域和交通规则；
- 数据库迁移与 API 契约；
- 三维模型与图片来源。

重大决策使用 ADR 记录背景、方案、取舍、兼容影响和验证方式。已经进入共享环境的 Flyway 迁移不得改写，后续变化必须新增迁移。

## 16. 北极星指标

产品建设优先回答三个问题：

1. 玩家是否能理解每个调度选择为什么赚钱、亏损、成功或失败？
2. 相同输入是否能够稳定重现相同任务和经营结果？
3. 新系统是否让车队结构、路线和风险之间产生更丰富而非更单一的策略？

当一个功能不能增强经营闭环、策略深度、可解释性或可复现性时，不应进入近期关键路径。
