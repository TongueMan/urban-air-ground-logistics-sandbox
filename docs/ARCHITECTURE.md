# 城市空地协同物流运营沙盘架构

## 设计目标

系统以服务端权威仿真为核心，保证任务生成、资产绑定、设备运动、电量、空域规则和经济结算可以复现、审计并在断线后恢复。前端负责空间呈现与操作，不直接写入业务结果。

## 运行拓扑

```text
浏览器（签名 HttpOnly Cookie）
├─ Vue 3：规划、车队、运行控制、结算与回放
├─ MapV Three / Three.js：三维城市、空地路线与设备模型
├─ REST / SSE ─────────────────────────┐
└─ WHEP / MP4 fallback ────────────┐   │
                                    │   │
Nginx（唯一业务 HTTP 入口）         │   │
├─ /api/* ── Spring Boot ───────────┘   │
├─ /media/* ── MediaMTX ────────────────┘
└─ 静态前端与 MP4 降级资源

Spring Boot
├─ 任务模板、确定性生成与路线校验
├─ 运行状态机、遥测、SSE 增量缓冲与检查点
├─ 车队资产、充电、采购、出售与账本
├─ 交通信号和空域规则引擎
├─ 百度路线 Provider Adapter
├─ DeepSeek 解释 Provider Adapter
├─ MQTT ── Mosquitto
└─ JDBC / Flyway ── MySQL 8.4

FFmpeg 媒体发布器 ── RTSP ── MediaMTX ── WHEP ── 浏览器
```

## 权威数据流

```text
任务模板 + Seed + 玩家参数 + 已出站资产
                    │
                    ▼
         生成并校验不可变任务实例
                    │
                    ▼
        开始运行并冻结具体设备与属性版本
                    │
                    ▼
   仿真推进 ── 遥测 ── 空域/交通判定 ── 账本结算
        │                                │
        ├──────── SSE 增量 ──────────────┤
        └──────── MySQL 持久化 ──────────┘
                    │
                    ▼
             浏览器呈现与任务回放
```

任务计划保存路线制品、模板与生成器版本、Seed、参数、约束校验和资产快照。任务回放读取实际保存的遥测，不重新运行当前版本生成器。

## 服务职责

| 服务 | 职责 | 不负责 |
| --- | --- | --- |
| Frontend | 交互、三维呈现、状态订阅、媒体播放 | 结算、所有权判定、权威运动 |
| Spring Boot | 任务、仿真、车队、经济、规则与接口 | 浏览器三维渲染 |
| MySQL | 公司、资产、任务、运行、事件、遥测、账本、决策 | 实时推送 |
| Mosquitto | 仿真遥测消息总线 | 长期业务存储 |
| MediaMTX | WHEP 媒体分发 | 任务状态与权限 |
| FFmpeg publisher | 将共享视频源循环发布到 MediaMTX | 业务判定 |

## 隔离与一致性

- Cookie 只保存随机访客标识与 HMAC 签名，不暴露数据库主键。
- 公司、资产、任务实例、运行、事件和账本查询均执行访客所有权校验。
- 同一访客同时只有一个非终态运行；并发创建和幂等命令由服务端约束。
- SSE 使用单调 revision 与增量缓冲，客户端可通过 `Last-Event-ID` 恢复。
- 账本写入以业务键去重，重试不能重复发放收益或重复扣款。
- 任务开始时校验冻结资产仍处于出站、可用且未被其他任务占用的状态。

## 外部服务边界

### 百度地图

- 浏览器端 AK 只用于地图展示，并通过运行时配置注入。
- 服务端路线 AK 只在后端使用。
- 路线服务不可用时使用任务模板定义的保底路线，并将来源写入任务制品。

### DeepSeek

- 后端先独立计算方案、资格、排序、成本和风险。
- 模型只生成解释文本，不能修改计算事实。
- 未配置密钥或请求失败时返回确定性规则解释。
- 真实设备命令链路不可用时，批准方案仍保持不可执行状态。

## 部署与容量

- 基础 Compose 包含 MySQL、Mosquitto、MediaMTX、媒体发布器、后端和前端六个服务。
- 生产覆盖配置面向 2 核 4 GB 主机，默认最多 12 个活动任务、100 个排队访客。
- Nginx 的 `8088` 是唯一业务 HTTP 入口；WebRTC 使用 TCP/UDP `8189`。
- MySQL 与 MQTT 使用命名卷；普通 `docker compose down` 不删除数据。

## 当前技术边界

- 空域几何按 2.5D footprint + 高度范围计算。
- 建筑碰撞尚未进入权威判定。
- 媒体是共享只读演示素材，不按访客生成。
- 系统不连接现实车辆或航空器。
